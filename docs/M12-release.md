# M12 测试与发布检查

## 本地回归

在项目根目录使用 Node.js 22 或更新版本运行以下命令。自动化流程用测试数据覆盖标准版 60 题、按身份续答、提交计分、保存与重开报告、取消删除和清除数据。其余测试覆盖题库、路由、旧记录迁移、写入失败、商业接口关闭和分享隐私。

```powershell
node --test tests/*.test.js
node scripts/check-release.js
```

发布检查只读取配置和开关。入口为 `touristappid` 或命令行无法读取项目配置时，检查返回失败。若命令行看到受保护格式，请在微信开发者工具中确认项目有效配置，并按设备的文件保护规则核验源文件。

## 模拟器与真机验收

使用测试测评数据执行以下步骤，保留已有答卷和报告。

1. 从首页进入标准版，选择「高中生、大学生」，答两题后退出。选择「职场新人」答一题，再切回「高中生、大学生」，核对两份草稿的题号和答案。已有旧版「职场人士」草稿时，核对续答入口。
2. 完成 60 题，核对六维分数和报告。切换到 180 天，保存报告，再从历史详情重新打开。分别查看学生和职场版本。
3. 在知识库切换兴趣类型，打开岗位和案例详情。复制公开来源链接，核对实际粘贴内容。
4. 从结果页发起分享预览，核对标题为产品介绍、落地页为首页。确认答卷、分数、兴趣代码和记录 ID 均未带入分享。
5. 在「数据与隐私」页面先取消删除，再用测试数据执行删除。核对删除单份草稿、单条历史和全部清除的范围。
6. 在 iOS 和 Android 手机上各运行一次核心流程，检查长文本、按钮可点击性、返回路径和离线续答。

## 提审与发布

- [ ] 由项目负责人在微信公众平台确认正式 AppID、主体、类目及操作权限。
- [ ] 核对平台上的隐私保护指引，按实际功能说明本机存储、分享落地页和复制来源链接。确认提审包没有真实答卷、测试夹具和账号信息。
- [ ] 在微信开发者工具检查代码包内容，确认测试、脚本和开发文档的排除设置适用于正式配置。
- [ ] 完成真机验收后，上传开发版，按需要设为体验版，由有权限的负责人提交审核。
- [ ] 审核通过并获得发布确认后上线。首发后复核首页、标准版测评、报告和数据管理。

平台入口及指引见 [微信公众平台](https://mp.weixin.qq.com/) 和 [腾讯云小程序隐私指引说明](https://cloud.tencent.com/document/product/1301/97930)。
